## Historical research and design records

The discovery, capability, Core-validation, catalogue-design and original application-design documents record how the current implementation was reached. Their dated observations remain useful for provider constraints, but proposed package layouts or “next steps” are not authoritative.

Captured `.html` and `.json` responses are provider research fixtures. They are not shipped in release packages or used as application runtime data.

When behaviour changes, update the maintained documents above first. Retain a research document only when it explains a provider-specific constraint or decision that is not evident from the current implementation.
